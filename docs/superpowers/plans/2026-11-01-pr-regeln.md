# PR-Regeln – Bauplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eine Regeldatei für PR-Regeln, ein Prüfprogramm, ein Claude-Code-Plugin (Hook und Skill `pr-anlegen`) und die Anbindung von pr-pruefen, Team-Cockpit, Vorlagen und Branch-Schutz-Meldungen, alles bis T0 nur warnend.

**Architecture:** `lib/pr-rules.mjs` ist rein (keine Netzzugriffe, keine Abhängigkeiten) und wird von `cli.mjs`, `scripts/pr-guard.mjs`, `scripts/pr-anlegen.mjs` und dem Cockpit genutzt. Netzzugriffe stehen nur in `lib/forges.mjs`. Das Repo ist zugleich das Plugin-Verzeichnis.

**Tech Stack:** Node ≥ 22, ESM, `node --test`, `gh` für GitHub, REST mit Basic-Auth für Bitbucket. Cockpit: TypeScript, vitest.

**Spec:** `docs/superpowers/specs/2026-11-01-pr-regeln-design.md`

## Global Constraints

- Code, Bezeichner, CLI-Optionen, Kommentare englisch; Kommentare nur ASCII, ohne Namen, Daten, Runden. Meldungen an Menschen deutsch.
- Keine Abhängigkeiten in `lib/pr-rules.mjs`; Node ≥ 22.
- Kein Ordner `bin/` im Repo.
- Tests nur mit erfundenen Beispielen; keine Texte aus privaten Repos im Repo.
- Stichtage `T0`, `T1`, `T2` sind `null`, bis sie gesetzt werden. Solange `T1` `null` ist, ist kein PR „neu“, der Hook verweigert nie, alle Funde sind Hinweise. Ausnahme: die Migrationsregel (3.6) gilt immer.
- Der Hook gibt nie `allow` aus; bei einem Absturz läuft der Befehl weiter.
- Zugangsdaten nie ausgeben.
- Kein Status an PRs (E387 C).

## Review Focus

1. Bitbucket-Texte mit Backslash-Escapes, eingerückten und umbrochenen Kopfzeilen: Kopfblock muss trotzdem erkannt werden, K1 statt Stille.
2. Wendungen in Codeblöcken, Inline-Code, HTML-Kommentaren und im Abschnitt „Abhängigkeiten und Reihenfolge“ dürfen nie K5 auslösen.
3. Hook: `gh pr create` in Heredocs, Here-Strings, `echo`, `grep`, `Select-String` darf nichts auslösen; Push eines schon gepushten Branches mit altem Namen bleibt still.
4. Migrationen: `dropIfExists` in `down()` zählt nicht; ein Hunk ohne erkennbare Funktion zählt als löschend (sichere Richtung).
5. Verneinte Kopfzeilen (`Merge-Stopp: keiner`) sind K2 und bleiben für das Cockpit ein Stopp.

### Task 2: Kopfblock (K1–K4, K6)

**Files:** Modify `lib/pr-rules.mjs`; Create `test/head.test.mjs`

**Produces:**
- `normalizeBody(body: string, forge: 'github'|'bitbucket'): string` – CRLF → LF; Bitbucket: Backslash vor Markdown-Zeichen entfernen.
- `parseHeadBlock(body: string): { entries: {key, value, line}[], end: number, needs: {repo, number, note}[], stops: string[], pairedWith: {repo, url}[], findings: Finding[] }`
- `Finding = { code: 'K1'|'K2'|'K3'|'K4'|'K5'|'K6'|'K7'|'K8'|'K9'|'M1'|'W…', message: string, fix?: string }`

Regeln: Kopfblock = Zeilen ab Zeile 1 mit Schlüssel in Spalte 0. K1: Schlüssel weiter unten, eingerückt, fett, mit Backslash oder vertippt (`Merge-Stop:`, `Merge Stopp:`, `Braucht :`, `Paired with:`), nicht in Codeblöcken. K2: verneinte Werte. K3: `Braucht:` nicht genau `<repo>#<n>` am Anfang, oder zweiter Verweis in derselben Zeile. K4: `Paired-with:` ohne https-Link als letztes Wort. K6: `Merge-Stopp:` leer. Verneinte `Merge-Stopp:`-Zeilen landen trotzdem in `stops`.

- [ ] Tests (erfunden): sauberer Block mit allen vier Schlüsseln; `Merge-Stopp: keiner` → K2 und `stops` enthält ihn; `Braucht: nichts` → K2; `Braucht: #12` → K3; `Braucht: fusion-api-v3#1 und #2` → K3; `Braucht: fusion-api-v3 feat/x` → K3; `Paired-with: canou-hub feat/x` → K4; `Merge-Stopp:` leer → K6; eingerückte Zeile mit `Merge\-Stopp:` auf Bitbucket nach `normalizeBody` → K1; `**Merge-Stopp:** x` → K1; `Kein Merge-Stopp mehr: …` in Zeile 5 → kein K1 (die Zeile beginnt nicht mit dem Schlüssel); `Merge-Stopp: x` in einem Codeblock weiter unten → kein Fund.
- [ ] Rot, umsetzen, grün, Commit.

### Task 7: Hook `pr-guard`

**Files:** Create `scripts/pr-guard.mjs`, `lib/shell.mjs`, `test/guard.test.mjs`, `hooks/hooks.json`

**Produces:**
- `splitCommands(command: string): string[][]` – zerlegt an `;`, `&&`, `||`, `|`, Zeilenumbrüchen unter Beachtung von Anführungszeichen; Heredoc- und Here-String-Inhalte fallen weg; einfache wörtliche Zuweisungen (`$x='…'`, `x="…"`) werden in späteren Segmenten ersetzt.
- `evaluate(toolName: string, toolInput: object, ctx: { cutoffs, now, remoteHasBranch(dir, branch): boolean, currentBranch(dir): string|null, readFile(path): string|null }): { findings: Finding[], deny: boolean }`
- `pr-guard.mjs` liest stdin, ruft `evaluate`, schreibt bei Funden vor T1 `{"hookSpecificOutput":{"hookEventName":"PreToolUse","additionalContext":"…"}}`, ab T1 `permissionDecision: "deny"` mit Grund; sonst nichts; Fehler → nichts, Exit 0; zählt Treffer in `${CLAUDE_PLUGIN_DATA}/hits.json`.
- `hooks.json`: PreToolUse, Matcher `Bash|PowerShell` und `mcp__.*__(create|update)_pull_request`, Exec-Form `node ${CLAUDE_PLUGIN_ROOT}/scripts/pr-guard.mjs`, Timeout 5.

Geprüft wird nach Spec 4.2: neue Branches, `git push` neuer Branches mit falschem Namen, `gh pr create`/`gh pr edit` mit wörtlichen Angaben, `POST`/`PUT` auf `…/pullrequests` und `gh api … /pulls` mit `POST` ohne `pr-anlegen` (Hinweis auf `pr-anlegen`), MCP-Werkzeuge.

- [ ] Tests: `git checkout -b feature/x` → Fund mit Vorschlag `feat/x`; `git switch -c feat/x` → nichts; `echo "gh pr create --title x"` → nichts; Heredoc mit `gh pr create` im Text → nichts; `git push -u origin feature/old` mit vorhandenem Remote-Branch → nichts; ohne → Fund; `git push origin --delete feature/x` → nichts; `gh pr create --head feat/x --base main --title t --body "Merge-Stopp: keiner"` → K2; `$b='feature/y'; git checkout -b $b` → Fund; `git -C $repo push` mit unbekannter Variable → nichts; `curl -X POST …/pullrequests` → Hinweis auf `pr-anlegen`; Aufruf mit `pr-anlegen.mjs` → nichts; vor T1 nie `deny`, mit T1 in der Vergangenheit `deny`.

### Task 8: Skill `pr-anlegen`

**Files:** Create `scripts/pr-anlegen.mjs`, `lib/body.mjs`, `test/body.test.mjs`, `skills/pr-anlegen/SKILL.md`

**Produces:**
- `buildBody({ text, needs, stops, pairedWith, after }): string` – Kopfblock in der Reihenfolge der Tabelle 3.2, Leerzeile, dann der Text; ein vorhandener Kopfblock im Text wird ersetzt.
- `pr-anlegen.mjs create|update|ready --repo-dir <pfad> --base <b> --title <t> --body-file <datei> (--ready|--draft) [--needs <repo>#<n>]… [--stop "<grund>"]… [--paired-with <repo> <url>] [--after "<schritt>"]… [--dry-run]`
  - create: Forge aus `origin`; `claude/…` → Fehler mit Vorschlag (Umbenennen per `git branch -m` und Push unter neuem Namen, wenn `--rename-to <name>` angegeben); Push, wenn nötig; Diff gegen Base für 3.6; Bitbucket mit löschender Migration → Stopp-Zeile; `checkPr` → rot = nichts anlegen; GitHub `gh pr create` mit Art-Label und `🔑 Marcs Ja fehlt` bei Migration; Bitbucket `POST` mit `draft`; Ausgabe: PR-Adresse.
  - update: Kopfblock und Text eines offenen PRs neu schreiben (`--number <n>`).
  - ready: Entwurf aufheben, wenn `checkPr` keine errors hat.
  - `--dry-run`: zeigt Text, Labels und Funde, legt nichts an.
- `SKILL.md`: springt an bei „PR anlegen/öffnen“, Release- und Rückführungs-PRs; Text zuerst in eine Datei im Scratchpad; Aufruf über `node "${CLAUDE_PLUGIN_ROOT}/scripts/pr-anlegen.mjs"` – da die Variable in Bash-Befehlen fehlt, steht im Skill der Weg über den Basisordner des Skills.
